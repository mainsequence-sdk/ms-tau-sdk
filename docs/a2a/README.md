# A2A Interface

This document is the operational contract for Astro's public Agent-to-Agent interface.
It describes the endpoints that exist now, what each one actually does, and the current
phase-1 limitations.

Testing contract: see [testing.md](./testing.md).

Astro no longer exposes the old Astro-specific A2A chat route. Public A2A clients must use
the standard REST-style routes under `/api/a2a/v1` or the JSON-RPC binding at `/api/a2a/rpc`.

## Runtime Model

Astro maps A2A `message.contextId` to an existing Main Sequence `AgentSession.uid`.

The backend still owns session creation, target-session allocation, model binding, and checkpoint
state. Astro does not create backend sessions from public A2A requests.

For phase 1:

- `message.messageId` is required and must be generated by the client. Reuse the same
  `messageId` when retrying the same logical message.
- `message.contextId` is required and must be an existing `AgentSession.uid`.
- The same `message.contextId` keeps the same backend conversation/session.
- `POST /api/a2a/v1/message:send` is idempotent by `(message.contextId, message.messageId)`.
  Reusing the same pair with the same request returns the in-flight or completed result.
  Reusing the same pair with different request content returns a conflict.
- Public A2A execution dispatches through shared in-process runtime functions. It does not
  HTTP-call `/api/chat`, `/api/a2a/chat`, or any runtime chat route.
- Runtime bootstrap, checkpointing, provider credentials, and warm-runner reuse are implementation
  details behind `message:send`. The first message for a cold session may pay the bootstrap cost;
  later messages reuse the same warm runner while the pod/process keeps it alive.
- Public A2A responses omit Pi reasoning, tool traces, and raw text-delta internals.

## Endpoint Status

| Endpoint | Methods | Status | Notes |
| --- | --- | --- | --- |
| `/api/a2a/v1/message:send` | `POST` | Implemented | Main non-streaming execution path. Returns a direct `message` by default, or a `task` when `configuration.returnImmediately` is true. |
| `/api/a2a/v1/message:stream` | `POST` | Implemented, minimal stream | Creates a task, emits task snapshots over SSE, and ends. It does not stream raw Pi token/tool chunks. |
| `/api/a2a/v1/tasks` | `GET` | In-memory phase 1 | Lists tasks held by the current Astro process only. |
| `/api/a2a/v1/tasks/{taskId}` | `GET` | In-memory phase 1 | Reads one task held by the current Astro process only. |
| `/api/a2a/v1/tasks/{taskId}:cancel` | `POST` | In-memory phase 1 | Cancels an active local runtime turn when present and marks the in-memory task canceled. |
| `/api/a2a/v1/tasks/{taskId}:subscribe` | `GET`, `POST` | Minimal phase 1 | Emits the current task state once as SSE and closes. This is not a long-lived live subscription yet. |
| `/api/a2a/v1/tasks/{taskId}/pushNotificationConfigs` | `GET`, `POST` | Config store only | Stores/list configs in memory. It does not deliver webhooks yet. |
| `/api/a2a/v1/tasks/{taskId}/pushNotificationConfigs/{configId}` | `GET`, `DELETE` | Config store only | Reads/deletes in-memory push notification config records. |
| `/api/a2a/v1/extendedAgentCard` | `GET` | Implemented | Session-scoped backend Agent Card lookup. Requires an agent session uid. |
| `/api/a2a/rpc` | `POST` | Implemented | JSON-RPC 2.0 binding over the same handlers. |

Not implemented yet:

- `/.well-known/agent-card.json`
- persisted A2A tasks across pod/process restart
- live task subscription fanout
- push notification delivery/webhooks

## Request Identity

Public A2A callers do not provide `user_uid`.

A2A is session-bound: `message.contextId` is the existing backend `AgentSession.uid`.
Astro hydrates that backend session for agent identity, model binding, checkpoint/session
state, and project/runtime attachment. A2A does not derive or require a user identity from
`AgentSession`; Pi runs with the runtime/deployment credentials already available to the
Astro deployment.

## `message:send`

Use this for normal request/response A2A calls.

```http
POST /api/a2a/v1/message:send
Content-Type: application/a2a+json
Accept: application/a2a+json
```

```json
{
  "message": {
    "messageId": "msg-1",
    "role": "ROLE_USER",
    "contextId": "0b2701a1-e777-4cfe-8437-b94025f00069",
    "parts": [
      {
        "text": "Summarize the current portfolio drift."
      }
    ]
  },
  "configuration": {
    "acceptedOutputModes": ["text/plain"],
    "returnImmediately": false
  }
}
```

`message.contextId` is the backend `AgentSession.uid`. Keep using the same `contextId` to continue
the same conversation. Generate a new `message.messageId` for each new logical message. If a request
times out or the client retries the same logical message, reuse the same `messageId`.

Default successful response:

```json
{
  "message": {
    "role": "ROLE_AGENT",
    "messageId": "msg-runtime-output",
    "contextId": "0b2701a1-e777-4cfe-8437-b94025f00069",
    "parts": [
      {
        "text": "..."
      }
    ]
  }
}
```

If `configuration.returnImmediately` is true, Astro creates an in-memory task, starts execution in
the background, and returns the task immediately:

```json
{
  "task": {
    "id": "task-...",
    "contextId": "0b2701a1-e777-4cfe-8437-b94025f00069",
    "status": {
      "state": "TASK_STATE_SUBMITTED",
      "timestamp": "2026-06-17T12:00:00.000Z"
    }
  }
}
```

## Strict JSON / Dictionary Output

Use `configuration.acceptedOutputModes` plus the Main Sequence output-contract metadata extension.

```json
{
  "message": {
    "messageId": "msg-json-1",
    "role": "ROLE_USER",
    "contextId": "0b2701a1-e777-4cfe-8437-b94025f00069",
    "parts": [
      {
        "text": "Return a JSON dictionary with keys ok, answer, and example."
      }
    ]
  },
  "configuration": {
    "acceptedOutputModes": ["application/json"],
    "returnImmediately": false
  },
  "metadata": {
    "https://mainsequence.ai/a2a/extensions/output-contract/v1": {
      "response_format": {
        "type": "dictionary",
        "strict": true
      },
      "jsonRepairAttempts": 3
    }
  }
}
```

For public A2A, Astro suppresses reasoning/tool traces from the returned response. For strict JSON,
Astro validates the final assistant text and attempts repair before returning a response. If validation
and all repair attempts fail, Astro returns an A2A error instead of returning invalid JSON.

## `message:stream`

Use this when the caller wants SSE task updates.

```http
POST /api/a2a/v1/message:stream
Content-Type: application/a2a+json
Accept: text/event-stream
```

Current phase-1 behavior:

- creates an in-memory task
- emits an initial task event
- waits for runtime completion
- emits a final task event
- closes the stream

It does not expose raw Pi chunks such as reasoning, tool calls, or text deltas.

## Task Endpoints

Tasks are process-local in phase 1. They are stored in memory and disappear on process restart.

`GET /api/a2a/v1/tasks` returns every in-memory task:

```json
{
  "tasks": []
}
```

`GET /api/a2a/v1/tasks/{taskId}` returns one task:

```json
{
  "task": {
    "id": "task-...",
    "contextId": "0b2701a1-e777-4cfe-8437-b94025f00069",
    "status": {
      "state": "TASK_STATE_COMPLETED",
      "timestamp": "2026-06-17T12:00:00.000Z"
    },
    "artifacts": [
      {
        "artifactId": "artifact-1",
        "parts": [
          {
            "text": "..."
          }
        ]
      }
    ]
  }
}
```

`POST /api/a2a/v1/tasks/{taskId}:cancel` attempts to cancel an active local runtime turn for the task.
If no local active turn exists, it only updates the in-memory task state when the task exists.

`GET|POST /api/a2a/v1/tasks/{taskId}:subscribe` currently writes the current task state once as SSE
and closes. It is not a durable live subscription yet.

## Push Notification Configs

Push notification config endpoints currently store config records in memory only:

- `GET /api/a2a/v1/tasks/{taskId}/pushNotificationConfigs`
- `POST /api/a2a/v1/tasks/{taskId}/pushNotificationConfigs`
- `GET /api/a2a/v1/tasks/{taskId}/pushNotificationConfigs/{configId}`
- `DELETE /api/a2a/v1/tasks/{taskId}/pushNotificationConfigs/{configId}`

They do not deliver webhooks yet.

## JSON-RPC Binding

`POST /api/a2a/rpc` accepts JSON-RPC 2.0 envelopes and maps them to the same handlers as the REST
routes.

```http
POST /api/a2a/rpc
Content-Type: application/json
```

Supported methods:

| JSON-RPC method | Equivalent REST route |
| --- | --- |
| `SendMessage` or `message/send` | `POST /api/a2a/v1/message:send` |
| `SendStreamingMessage` or `message/stream` | `POST /api/a2a/v1/message:stream` |
| `GetTask` or `tasks/get` | `GET /api/a2a/v1/tasks/{taskId}` |
| `ListTasks` or `tasks/list` | `GET /api/a2a/v1/tasks` |
| `CancelTask` or `tasks/cancel` | `POST /api/a2a/v1/tasks/{taskId}:cancel` |

Example:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "SendMessage",
  "params": {
    "message": {
      "messageId": "msg-1",
      "role": "ROLE_USER",
      "contextId": "0b2701a1-e777-4cfe-8437-b94025f00069",
      "parts": [
        {
          "text": "Hello"
        }
      ]
    },
    "configuration": {
      "acceptedOutputModes": ["text/plain"],
      "returnImmediately": false
    }
  }
}
```

Success response:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "message": {
      "role": "ROLE_AGENT",
      "messageId": "msg-runtime-output",
      "contextId": "0b2701a1-e777-4cfe-8437-b94025f00069",
      "parts": [
        {
          "text": "..."
        }
      ]
    }
  }
}
```

## Agent Card

`GET /api/a2a/v1/extendedAgentCard` always asks the backend for the Agent Card attached to an
existing backend `AgentSession`.

Astro calls:

```http
GET /orm/api/agents/v1/sessions/{session_uid}/agent-card/
```

Callers must provide the session uid using one of:

- query: `agent_session_uid`
- query: `agentSessionUid`
- query: `session_uid`
- query: `sessionUid`
- query: `contextId`
- query: `context_id`
- header: `X-Agent-Session-Uid`

Response shape:

```json
{
  "agent_session_uid": "0b2701a1-e777-4cfe-8437-b94025f00069",
  "agent_uid": "agent-uid",
  "agent_card": {
    "name": "Agent name"
  }
}
```

The public well-known card at `/.well-known/agent-card.json` is intentionally deferred until the
public discovery contract is stable.
